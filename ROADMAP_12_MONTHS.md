# NOVA AI — Evidence-Gated 12-Month Roadmap

Dates are planning windows, not delivery promises. No paid service/API spend is assumed.

## Days 0–30 — Make candidate verifiable

- Owner configures Staging Health Check Path as `/health`; diagnose why Auto Deploy is not moving the service to current PR head.
- Deploy exact candidate to the existing Staging URL and run live health/routes/config/provider/account smoke.
- Enable Express API authentication on Staging only; test missing, invalid, expired and valid tokens plus outage behavior.
- Run physical Android tests for full width, drawer, touch targets, keyboard and microphone.
- Replace, disable or obtain suitable commercial rights for every restricted/undocumented provider path.
- Finalize account deletion/retention design and verify no customer data is accepted prematurely.

**Exit evidence:** exact Staging SHA, live smoke report, physical handset record, Auth tests, approved provider rights matrix and reviewed data lifecycle.

## Days 31–90 — Close security and portability

- Add durable DB-backed Express quotas, monthly accounting, provider budgets, abuse controls and kill switches.
- Implement full Auth/account data deletion with verified cascades and retention schedule.
- Run two-account/two-device sync and tenant-isolation tests, including interrupted network recovery.
- Export/restore Supabase backup in isolated environment; document RPO/RTO and owner.
- Add centralized error/availability evidence; privacy-safe operational telemetry.
- Complete Deno/source/media/font/icon/video/CDN licence and asset provenance, SBOM, notices bundle.
- Complete source docs and full API contract.

**Exit evidence:** quota/deletion/restore proof, verified rights, second-host deploy, operational report.

## Months 4–6 — Validate a narrow problem

- Choose one user segment after consent-based research with adults and a documented recurring problem.
- Compare one workflow against at least three current alternatives using identical inputs.
- Measure completion rate, correction time, evidence quality, reliability and cost per successful result.
- Use only synthetic/non-sensitive data until privacy/security/support contracts are approved.
- Improve only where user data proves measurable value.

**Exit evidence:** reproducible benchmark, real permission-based feedback and repeat-use evidence; no fabricated claims.

## Months 7–9 — Prepare controlled pilot

- Obtain final support ownership, incident procedures, legal/privacy/age-consent review, vendor DPAs and provider rights.
- Build versioned API v1, TypeScript SDK, signed webhooks and plugin permission system only after auth, tenancy and durable quotas pass.
- Add admin/role controls to core workspace only when a validated use case requires them.
- Set prices from actual usage costs and willingness-to-pay; do not invent unit economics.
- Launch only a tightly scoped supervised pilot after qualified review.

**Exit evidence:** reviewed pilot, stable API, provider/legal clearance, measured costs and tested support/recovery.

## Months 10–12 — Earn measurable repeat use

- Fix onboarding drop-offs based on observed data.
- Track active users, activation, task success, retention, paid conversion only after billing approval, churn, gross margin, support response and uptime.
- Publish metrics only when reconcilable to first-party logs and accounts.
- Decide whether to scale, narrow or stop based on measured retention and margins.

**Exit evidence:** auditable cohort metrics, permitted user feedback and updated independent valuation.

## Differentiation hypotheses — not unique-feature claims

1. Evidence-first output bundle: input provenance, sources, assumptions, version, validation and replayable tests.
2. Hindi-English learning-to-building path: course/source material to tested, exportable artifact.
3. Human-approved small-business decision trace: metrics to approval to post-action measurement.
4. Portable project handoff: source, variable names, deployment, restore and tests.

Competitors already document overlapping app-building, backend, deploy, Git and agent functions. No exclusive claim is approved before bounded comparison, benchmark and real-user validation.

## Tier 2 scenario arithmetic (not a forecast)

At an illustrative 3× ARR scenario, ₹10–20 crore would imply ₹3.33–6.67 crore ARR. At an assumed realized ₹999 per paid account per month, arithmetic gives roughly 2,800–5,600 paid accounts before churn, discounts, failed payments, taxes, refunds, costs or concentration. This is not a price recommendation, forecast or valuation.
